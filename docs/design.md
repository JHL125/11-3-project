# 비플페이 식당 지도 — 설계

작성일: 2026-11-03

## 1. 한 줄 요약

사용자가 웹 화면에 구획 이름(도로명 · 동 이름 · 지명)이나 자연어("강남역 근처 국밥집")를 입력한다.
- Gemini가 입력을 해석한다.
- 내 PC의 Aside가 네이버 지도에서 구획 좌표를 가져온다.
- 공공데이터포털 **소상공인 상가(상권)정보 API**에서 구획 안 식당 목록을 가져와 웹 지도(Vercel)에 표시한다.

누구나 식당을 눌러 비플페이 가능/불가능을 고를 수 있고, 결과는 모든 사용자 지도에 바로 반영된다.

## 2. 구조

```
[사용자 브라우저] ─입력─▶ [Vercel: /api/request] ─Gemini 해석─▶ [Supabase] regions.status = pending
      ▲                                                              │
      │ 실시간 반영(Realtime)                                          ▼
      └──── [Supabase] ◀─ 저장 ─ [내 PC 수집기] ─▶ ① aside CLI → 네이버 지도(구획 좌표)
                                                 ─▶ ② 상가정보 API(식당 목록)
```

- **왜 수집기가 내 PC에 있나**: Aside는 내 PC에 설치된 브라우저라서 Vercel 서버가 직접 부를 수 없다.
- **제약**: PC가 꺼져 있거나 수집기가 멈춰 있으면 **새 구획은 수집되지 않는다.** 이미 수집한 구획의 지도와 버튼은 PC와 관계없이 동작한다.

## 3. 요구사항 → 구현 방법

| 요구사항 | 구현 |
|---|---|
| 도로명 · 동 이름 · 지명 입력 | `/api/request`가 Gemini로 해석한다 → `{구획명, 구획종류, 업종키워드}` |
| 구획 = 네이버 지도 폴리곤 | Aside가 네이버 지도에서 경계 · 도로 선 · 중심 좌표를 가져온다(4절) |
| 식당 목록 | 상가정보 API `storeListInPolygon`. 무료이고 누락이 적으며 빠르다(1,000건/초) |
| 식당이 아닌 업장 제외 | 업종 코드로 거른다(6절). 키워드가 있을 때만 Gemini가 한 번 더 고른다 |
| 모든 사용자에게 표시 | `bipl_status`와 Supabase Realtime |
| 의견이 갈리면 최신 응답 | 업장당 한 행을 덮어쓴다. 이력은 `bipl_votes`에 남긴다 |
| 가능 | 형광 핑크(#ff10f0) 테두리와 빛번짐이 1초 주기로 깜빡인다 |
| 불가능 | 회색 |
| 미확인 | 색 없음(흰 바탕, 어두운 테두리) |
| 지도 | Leaflet + OpenStreetMap(키 불필요). 마커가 잘 보이도록 배경 채도를 낮춘다 |
| 로그인 | 없음 |

## 4. 구획(폴리곤) 규칙

| 구획 종류 | 예 | 폴리곤 |
|---|---|---|
| 행정구역 | 역삼1동, 서교동 | 네이버 지도 경계 폴리곤 그대로. 못 받으면 중심 반경 700m 원으로 대체하고 화면에 표시 |
| 도로 | 테헤란로 | 도로 선을 양쪽 50m씩 넓힌 띠 모양 |
| 지명 · 랜드마크 | 강남역, 홍대입구 | 중심에서 반경 500m 원 |

## 5. 데이터 (Supabase)

- `regions` — 구획 요청과 결과
  - `query`, `name`, `kind`(admin/road/poi), `keyword`
  - `polygon`(GeoJSON), `center_lat`, `center_lng`
  - `status`(pending/collecting/done/failed), `error`
- `restaurants` — `region_id`, `place_key`(상가업소번호), `name`, `category`(업종 소분류), `address`, `lat`, `lng`
- `bipl_status` — `place_key`(PK), `status`(yes/no), `updated_at`. 업장당 최신값 한 행
- `bipl_votes` — 응답 이력

권한(RLS)

| 테이블 | 익명 사용자 | 서버(Vercel 함수 · 수집기, service role) |
|---|---|---|
| `regions` · `restaurants` | 읽기 | 읽기 · 쓰기 |
| `bipl_status` | 읽기, `set_bipl` 함수로만 변경 | 읽기 · 쓰기 |
| `bipl_votes` | 접근 불가(`set_bipl`이 기록) | 읽기 · 쓰기 |

비플페이 상태는 구획이 아니라 업장(상가업소번호) 단위로 저장한다. 그래서 겹치는 구획에서도 같은 상태가 보인다.

## 6. 수집기 흐름 (내 PC)

1. 10초마다 `pending` 요청을 하나 가져와 `collecting`으로 바꾼다
2. `aside` CLI에 `collector/aside-prompt.md`를 넘기면, Aside가 네이버 지도에서 좌표를 가져와 JSON으로 돌려준다
3. 좌표로 폴리곤을 만든다(4절)
4. 폴리곤을 100m 넓혀 단순화한 뒤 상가정보 API로 업장을 조회한다
5. 실제 폴리곤 안에 있는 업장만 남긴다
6. 업종 키워드가 있으면 Gemini로 한 번 더 고른다
7. 저장하고 `done`으로 바꾼다. 실패하면 `failed`와 오류 내용을 기록한다

**식당 판정 기준(확정) — 상가정보 업종 코드**
- 포함: 음식 대분류 `I2` 전체(한식 · 중식 · 일식 · 서양식 · 분식 · 카페 · 빵/도넛 · 아이스크림 등)와 편의점 `G20405`
- 제외: 주점 중분류 `I211`(일반 유흥 주점 · 무도 유흥 주점 · 생맥주 전문 · 요리 주점)

**검증 결과(2026-11-03, 실제 API)**

| 구획 | 업장 수 | 소요 시간 | 비고 |
|---|---|---|---|
| 강남역 반경 500m | 1,056곳 | 약 8초 | 주점 0곳, 편의점 59곳 포함 |
| 테헤란로(강남역~삼성역) 양쪽 50m | 213곳 | 약 4초 | |

## 7. 웹 화면

- 입력창: 구획 이름이나 자연어를 입력한다. 같은 구획이 이미 있으면 바로 보여 주고, 실패한 구획은 다시 수집 대기로 돌린다
- 최근 구획 칩: 누르면 해당 구획으로 이동한다. 주소 `#구획ID`로 공유할 수 있다
- 지도: 구획 폴리곤과 업장 마커를 표시한다
- 마커 클릭: 상호 · 업종 · 주소와 **[비플페이 가능] [불가능]** 버튼을 보여 준다
- 상태 줄: 업장 수와 가능 수, 또는 수집 대기 · 실패 사유를 보여 준다

## 8. 미정 · 확인 필요

1. **Aside CLI 미설치**: Aside 설정 → Developer에서 CLI를 설치하고 `aside login`을 해야 한다(사용자가 직접)
2. **Aside 결과 미검증**: 네이버 지도에서 경계 폴리곤 좌표를 실제로 뽑을 수 있는지 CLI 설치 후 실험해야 한다
3. **Aside 자체 AI 비용**: Aside가 브라우저를 조작할 때는 Aside 자체 모델을 쓴다
4. **Gemini 모델 이름**: 기본값은 `gemini-3.5-flash-lite`다. 다른 모델을 쓰려면 `GEMINI_MODEL`로 바꾼다
5. **OSM 타일 정책**: 공개 OSM 타일 서버는 대량 트래픽용이 아니다. 사용자가 많아지면 타일 제공 업체로 바꾼다
6. **상가정보 데이터 시점**: 분기마다 갱신된다(검증 시점 기준 2026년 9월). 새로 생기거나 폐업한 가게는 늦게 반영된다
7. **익명 투표**: 누구나 바꿀 수 있다. 이력 테이블로 되돌릴 수 있게만 해 둔다
8. **업장이 많은 구획**: 수천 개 마커는 휴대폰에서 느릴 수 있다. 필요하면 마커 묶음(클러스터)을 넣는다
